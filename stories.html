User stories

How we split the port into stories, what AMD asked us to change along the way, and where each story stands now.

How we planned the work

AMD's goal for the term was simple to say: define an environment in Godot, train it with Schola's Python tools, export the result to ONNX, and run it back in Godot. We broke that down into user stories, each with the user it serves, acceptance criteria, what's out of scope, and how we'd verify it.

  1. The first set was drafted on September 29 and approved by AMD on October 2. An export-validation story was dropped that day because Schola's Python side already exports models, which left US1 to US5 and US7.
  2. Between October 9 and 15, every owner merged a pull request containing only their story's API. With the interfaces agreed, nobody had to wait for someone else's implementation to start their own.
  3. Owners then built on their own branches, sometimes in pairs, and landed focused pull requests that each say how they were tested.
  4. After D2 we changed one thing: shared dependencies get merged before the code that uses them, and everything is tested against one runnable example.
  5. On November 6 AMD approved a second set, US8 to US14, split into must-haves and stretch goals. US15 came out of the same meeting.

What AMD changed

We met AMD every Friday. These are the conversations that ended up changing code.

Four separate step callbacks are ambiguous. AMD, October 23. Decided October 30.
Reward, termination, truncation and info now come back together from one _get_step_result(agent).
A built-in step limit will fight custom truncation rules. AMD, October 23 and 30.
We removed it, along with a step-limit node we'd planned. Developers return truncated: true when their own rule says so.
Delaying actions and rewards hurts learning. AMD, October 23.
We dropped the non-blocking poll. The connector waits once per physics frame, so an action and its reward always land on the same frame.
Can the sequence length come from the model? Our question, October 23. Approved as US14 on November 6.
ONNX Runtime's C API couldn't read the metadata where it was stored, so AMD changed Schola's exporter upstream. We then removed the manual setting. Unreal still sets it by hand.
Stackers should be general observation adapters. AMD, November 6.
ScholaStacker is the first adapter built on an abstract ScholaObservationAdapter, and agents can chain several.
Typing bounds into the Inspector gets tedious for big spaces. AMD, November 6.
That became US15, an optional function that defines spaces in code.
Too many repeated warnings. AMD, November 6.
Environments now show one warning summary per agent.

What we left out

An idea only became a story if it passed all five of these:

  • It solves a concrete problem a Godot developer has.
  • Schola behaves the same across engines.
  • It can't be done as a task inside an existing story.
  • AMD is happy to maintain it.
  • It doesn't hold up the end-to-end train, export and run workflow.

That's why Unreal-only features such as StateTree and imitation learning aren't being ported, and why running several environments inside one Godot process is a possible follow-up rather than a story.
