# US12: Train multiple agents simultaneously

- **Owner:** Unassigned
- **Status:** Proposed
- **Last updated:** Oct. 30, 2026

## Story

As an ML practitioner, I want to train multiple agents in one environment so that I can build cooperative and competitive reinforcement-learning scenarios.

## Rationale

Simultaneous multi-agent training is an expected outcome of the Godot port. The existing Schola protocol already represents agents independently, so Godot should prove that its environment, lifecycle, and transport layers preserve agent identity and correctly route each action and result.

## Acceptance criteria

- One environment can expose two or more agents to Python.
- Agents may declare different observation and action spaces where the existing Schola protocol supports them.
- Agent identifiers and their ordering remain stable for the lifetime of a training session.
- Actions, observations, rewards, termination, truncation, and info are routed to the correct agent.
- Cooperative agents may share rewards, while competitive agents may receive different rewards.
- Per-agent and environment-wide episode-completion behavior is documented and matches the existing Schola protocol.
- A supported Python trainer completes multiple episodes with at least two simultaneous agents.
- Tests cover duplicate IDs, missing or extra actions, different spaces, agent-specific results, resets, and session failure.
- The implementation does not introduce Godot-only multi-agent semantics.

## Scope limits

- This story validates the multi-agent behavior already represented by Schola; it does not add a new matchmaking, team, or league-training system.
- Dynamic addition or removal of agents during an active training session is excluded unless AMD approves corresponding protocol semantics.
