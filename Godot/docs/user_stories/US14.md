# US14: Read the state sequence length from the model

- **Owner:** Jimmy
- **Status:** Implemented and tested on feature branch
- **Priority:** Stretch goal
- **Last updated:** Nov. 19, 2026

## Story

As a Godot developer, I want a recurrent policy to take its state sequence length from the exported model so that I do not have to remember the training value and cannot get wrong actions from a mismatched setting.

## Rationale

Schola's exporter records `has_seq_dim`, `max_seq_len`, and `seq_dim` on each state input. `ScholaOnnxPolicy` currently ignores that metadata and uses `max_state_sequence_length`, which the developer sets by hand and which defaults to one. A wrong value produces wrong actions with no error. Unreal's `MaxStateSequenceLength` is also set by hand, so the outcome should be agreed with AMD to keep the engines consistent.

ONNX Runtime's C API exposes model-level custom metadata but not the metadata on individual inputs, so the exported value cannot currently be read through ONNX Runtime.

## Acceptance criteria

- A model that declares `max_seq_len` for a state input runs with that length without any manual setting.
- Invalid metadata, such as a non-integer or a value below one, produces a clear error when the policy initializes.
- Exported games gain no training or transport dependency, and the runtime add-on stays separate from the training add-on.
- Tests cover each case above and include a recurrent model with a sequence dimension exported by a real Schola trainer.
- The inference guide documents where the length comes from and when the manual setting applies.

## Progress

The [upstream metadata PR #58](https://github.com/GPUOpen-LibrariesAndSDKs/Schola/pull/58) merged on Nov. 18, 2026. It copies each state input's metadata into the model metadata as `<input>.<field>`, which ONNX Runtime can read. The shared exporter in this repository carries the same change.

`ScholaOnnxPolicy` now reads `has_seq_dim`, `max_seq_len`, and `seq_dim` for each state input when it loads a model. A declared length overrides `max_state_sequence_length`, which now applies only to models without that metadata. Invalid metadata fails the load, and therefore `initialize()`, with an error naming the key and value. The reader uses only ONNX Runtime, so the runtime add-on gains no dependency.

Catch2 and GdUnit4 tests cover a declared length, the manual fallback, and invalid metadata. They also cover a model with a sequence state exported through Schola's `ScholaModel` exporter, and the re-exported RLlib LSTM, which declares no sequence.

Schola's RLlib exporter cannot currently export an old-API-stack recurrent policy, which is the only trainer path that declares a sequence. It passes `seq_lens` as a Python list, so attention and LSTM exports fail in RLlib. The upstream attention export test is also disabled. Until AMD fixes this, no trainer produces a sequence-dimension model end to end. The sequence fixture therefore uses a small `ScholaModel` subclass through the same exporter.
