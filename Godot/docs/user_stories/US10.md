# US10: Stack recent observations

- **Owner:** Unassigned
- **Status:** Proposed
- **Last updated:** Oct. 30, 2026

## Story

As a Godot developer, I want to combine recent observations into a fixed-size history so that a policy can use temporal information without requiring a recurrent model.

## Rationale

Schola for Unreal provides Box and Dict stackers that retain a configurable observation history. The Godot port should preserve the same ordering, shape, default-value, and reset semantics while exposing stacker configuration through a reusable Godot Resource.

## Acceptance criteria

- Schola can stack Box observations and Dict observations.
- A developer can configure the number of observations retained in the history.
- Box stacking supports the same new-dimension and expanded-dimension behavior as Unreal Schola.
- Unfilled history entries use a configured default point compatible with the unstacked space.
- The stacker reports the complete stacked observation space before training or inference begins.
- The newest and oldest entries use a documented, deterministic ordering that matches Unreal Schola.
- Observation history resets at the beginning of an episode and cannot leak between episodes or agents.
- Invalid stack dimensions, sizes, spaces, or default points produce actionable validation errors.
- The same stacker behavior is available to training and local inference workflows.

## Godot interface

- Stacker configuration is represented by a Resource because it is reusable serialized data rather than spatial scene behavior.
- Mutable observation history is owned per agent; sharing one configuration Resource must not share episode state between agents.

## Scope limits

- This story does not add recurrent-policy support or change policy-state semantics.
- It does not introduce stacking behavior that cannot be represented by Unreal Schola.
