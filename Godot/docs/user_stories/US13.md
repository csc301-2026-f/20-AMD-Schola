# US13: Train and deploy through a production example

- **Owner:** Unassigned
- **Status:** Proposed
- **Last updated:** Oct. 30, 2026

## Story

As a new Schola user, I want a complete Godot example that trains through the production integration so that I can verify my setup and use the example as a starting point for my own environment.

## Rationale

The project specification requires an example environment in which an agent successfully learns. Earlier course demos are frozen historical artifacts and may contain temporary stand-ins, so the production workflow needs a new example that exercises the completed Godot integration end to end.

## Acceptance criteria

- The example uses the production environment, agent, lifecycle, and gRPC implementations without local transport or lifecycle stand-ins.
- Training runs through at least one Python framework already supported by Schola.
- A documented metric demonstrates reproducible learning beyond an untrained baseline.
- The trained policy can be exported to ONNX.
- Godot loads the exported policy and runs the learned behavior with Python closed.
- The example uses production sensor, actuator, space, and policy APIs where applicable.
- Setup, training, export, inference, and common failure recovery are documented from a clean checkout.
- Automated smoke tests verify that the example loads and that its production components are configured correctly.
- The example is created in a new current location; frozen D1 and D2 demos remain unchanged.

## Scope limits

- One well-documented benchmark environment is sufficient.
- Supporting every Python training framework in the example is not required; the engine protocol must remain compatible with the shared Schola Python stack.
- This story validates existing production components rather than creating a second implementation for the example.
