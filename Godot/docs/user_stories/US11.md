# US11: Observe the environment through a camera sensor

- **Owner:** Unassigned
- **Status:** Proposed
- **Last updated:** Oct. 30, 2026

## Story

As a Godot developer, I want an agent to receive image observations from a camera sensor so that I can train and run vision-based policies.

## Rationale

Schola for Unreal provides a camera sensor that converts rendered output into normalized observations. Godot should provide the same capability through its camera, viewport, texture, and image APIs after US8 establishes the common sensor interface.

## Acceptance criteria

- A reusable camera sensor participates in the sensor composition model defined by US8.
- A developer can configure observation width, height, and supported color channels through the Inspector.
- The sensor declares a Box observation space whose shape, bounds, and data type match the produced image values.
- Captured pixels use a documented channel order, tensor layout, normalization range, and frame timing.
- The implementation validates incompatible camera, viewport, image-format, and channel configurations before training or inference begins.
- Camera observations work during both Python training and local ONNX inference.
- The sensor operates correctly in the supported headless training configuration or reports a clear unsupported-configuration error.
- Tests cover observation shape, channel selection, normalization, capture timing, and repeated captures.
- The documented observation semantics correspond to Unreal Schola's camera sensor wherever the engines provide equivalent rendering data.

## Godot interface

- The sensor is a scene-owned node because it participates in the scene tree and camera lifecycle.
- Rendering is implemented with Godot-native camera and viewport APIs rather than an Unreal-shaped abstraction.
- Configuration problems appear as Inspector warnings; runtime capture failures use the shared Godot error-handling rules.

## Scope limits

- US8 must establish and validate the sensor composition contract before this story begins.
- Performance work is limited to producing camera observations reliably; asynchronous or pipelined inference is not part of this story.
- Support for depth, segmentation, or other specialized render passes requires explicit follow-up scope.
