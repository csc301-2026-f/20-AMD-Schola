- The presentation has a hard 20-minute limit. Going over it loses marks.
- Salman suggested this order:
  1. **Background (about 5 minutes):** the problem statement, discussions with the partner, and enough context for a TA who has not seen the project.
  2. **Demo.**
  3. **Internal architecture.**
  4. **Challenges and discussion.**
- The project is technical, so the presentation should not jump straight into implementation details. More background, examples, and framing of what the project solves should come first.

## D4 vs. D5 scope

- D4 is graded on the presentation. D5 is graded on how complete the codebase is.
- D4 is effectively the final feature-complete submission, the latest version of the MVP.
- D5 work is limited to CI/CD pipelines, documentation, and README updates.
- Refactoring counts as improving the product, so it should be finished before D4.
- Whether minor refactoring is allowed after D4 is a gray area. Because a different person grades D5, the team should confirm on Piazza.
- The current focus is finishing and polishing what is already built and making the app ready for the presentation.
