Schola for Godot

We're porting AMD Schola, a reinforcement learning toolkit for Unreal Engine, to Godot 4.7. You describe an environment with Godot nodes and a few GDScript functions, connect it to Schola's Python trainers, and ship the trained policy as an ONNX model that runs in your game without Python.

What we're building

Schola is AMD's open-source plugin for training game agents with reinforcement learning. In Unreal you define agents and environments in the engine, train them from Python with Gymnasium, Stable-Baselines3 or RLlib, and run the result in-game from an ONNX file. AMD wants Schola to work with more than one engine, and our job this term is Godot.

We kept everything Python sees the same. The Godot side speaks the same gRPC protocol as Unreal, generated from the same .proto files, so Schola's Python package doesn't need any Godot-specific code. Everything a Godot developer touches is new and follows Godot's own conventions: nodes, resources, the Inspector and GDScript.

The task we test with

From D2 onwards every demo used the same small problem: get across a 6×6 grid to the goal without stepping on a hazard.

  • The agent sees four numbers: its own position, and how far away the goal is.
  • It can move up, down, left or right.
  • Reaching the goal is worth +10 and a hazard −10. Every step costs 0.1, and an episode stops after 40 steps.

The arrows are the shortest-path policy we bundle with packaged builds, to check that inference works on every platform. It's a reference answer, not something the agent learned.

Where things stand

As of November 23, twelve of our fourteen user stories are merged on main:

  • Environments and agents built from Godot nodes, including agents that join or leave mid-episode
  • Box, Discrete, MultiDiscrete, MultiBinary and Dict spaces
  • The gRPC training connector, as a single node you add to a scene
  • The episode lifecycle that resets and steps every environment
  • Inspector configuration with live warnings, a Schola dock and a runtime monitor
  • ONNX inference, with exported games that leave training out
  • Reusable sensors and actuators
  • Stepping an environment by hand, without Python
  • Observation stacking
  • Several agents with different spaces training in one environment
  • Reading a recurrent model's sequence length from its metadata
  • Defining spaces in code instead of the Inspector

Still to come for Deliverable 4 on November 27: a full training run with Schola's own Python trainers, the RaceTrack production example, camera-based training, and a round of bug fixes and speed-ups across the merged stories.
