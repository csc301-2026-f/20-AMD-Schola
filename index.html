Reinforcement learning, native to Godot.

We are porting AMD Schola, a reinforcement learning toolkit built for Unreal Engine, to Godot 4.7 as a C++ GDExtension. Developers build environments from native nodes, connect them to Schola's Python trainers over the same gRPC protocol Unreal uses, and ship trained ONNX policies inside their game with no Python at runtime.

Define, train, ship.

Schola already let Unreal developers train agents with Python and run the result in-engine. AMD asked us for the same workflow in Godot, with a small core that is easy to extend.

  • Define an environment

    Add a ScholaEnvironment with ScholaAgent children, set their spaces in the Inspector, and write four GDScript hooks. Sensors and actuators can replace hand-written hooks.

  • Connect to training

    One ScholaTrainingConnector node serves Schola's GymService over gRPC, generated from the same .proto files Unreal and Python use. It lives in its own extension.

  • Ship the policy

    ScholaOnnxPolicy runs exported models through ONNX Runtime 1.30, including recurrent state. Exported games leave the training extension out entirely.

Eight weeks, three demos.

Each deliverable replaced a stand-in with production code.

  1. October 2, 2026

    D1: plan and prototype

    Six user stories approved by AMD, and a throwaway C# Inspector prototype. AMD's review moved us to a C++ GDExtension so the plugin works in every Godot build.

  2. October 23, 2026

    D2: the first full loop

    A 3D grid world trained by a local Python learner, then driven by an exported ONNX policy with Python closed. The spaces and inference were native; the lifecycle and transport were still stand-ins.

  3. November 6, 2026

    D3: native end to end

    The grid world rebuilt on native environments, agents and one training host, with a map editor, parallel training and packages tested on Windows, Linux and macOS.

  4. Since D3

    Production pieces

    The gRPC scene connector, sensors and actuators, observation stacking, a no-Python debugging example, sequence length read from model metadata, and dynamic agent populations.

Where it stands

The Godot side of training is merged and tested against a C++ client that speaks Schola's protocol. A full training run with Schola's own Python trainer, the RaceTrack production example and multi-agent training are still on branches heading for D4.

About the demosThe D2 and D3 demos train with a temporary JSON connector and a tabular learner, and the packaged D3 model is a shortest-path reference rather than a learned policy. We say so wherever they appear.
