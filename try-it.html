Try it

Two ways in: run our D3 demo in a couple of minutes, or set Schola up in your own Godot project.

Run the demo

The D3 demo is a packaged desktop app, so you don't need Godot or Python to run it.

  1. Download it for your system: Windows, Linux or macOS (Apple silicon).
  2. Unzip it and open the app. The app isn't signed, so your system may ask before opening it.
  3. Move the agent with the arrow keys. Press Policy to let the bundled model drive, and Stop to take control back.
  4. Press Edit map to change the layout. The bundled model only knows the default map, so press Default before running it again.

Training from the demo needs the source code and Python. The D3 demo guide covers that.

Use Schola in your own project

Schola for Godot isn't released as a packaged plugin yet, so for now you build it from source. These steps follow the Godot README, which has the full detail.

Build the plugin

You'll need Git with Git LFS, Python 3.12, Godot 4.7.2 and a C++17 compiler.

The build puts its libraries into Godot/addons/schola and Godot/addons/schola_training. Copy both folders into your project's addons folder, then turn on the AMD Schola plugin in Project Settings for the Schola dock and Inspector help.

Set up the scene

Add a ScholaEnvironment node with a ScholaAgent under it. In the Inspector, give the agent an observation space and an action space. Here the agent sees one of five cells and picks one of two moves.

Check it without Python

Before training, it's worth stepping the environment by hand to make sure the rewards and endings look right. Our manual environment example does exactly that, with a button for each action and a live monitor.

Train it from Python

Add a ScholaTrainingConnector node to the scene and run it. The connector waits for Python on port 8000. Within 45 seconds, start Schola's trainer from the same checkout:

For several agents with different spaces, use schola rllib train instead, which gives each agent its own policy.

Ship the trained policy

  • Add a ScholaOnnxPolicy resource and point its model_path at your exported .onnx file.
  • Add a ScholaInferenceStepper node, set its policy, and list the agents it should drive.
  • In your export preset, add *.onnx to the non-resource files to export, and exclude addons/schola_training/*.
  • Build the plugin with target=template_release for release exports.

The exported game runs the model itself, with no Python and no training code inside.
